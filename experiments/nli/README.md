# NLI / claim-extractor experiment

Throwaway mock of the chunk → claim → grounding path ([SPEC §6.1, §6.4](../../docs/SPEC.md#64-prose-and-changelog--claim)). Not part of `core/`, not run in CI.

Sources: **urllib3** (`docs/user-guide.rst` and `CHANGES.rst` @ `d07367d`, the recommended pilot library) and one **httpx** section (`docs/advanced/timeouts.md` @ `b5addb6`, Markdown/MkDocs). The reader output (Sphinx doctree / Markdown AST) is simulated by hand in `section.json`, with the text copied verbatim. Block types: `paragraph`, `list_item`, `admonition` (prose, in NLI windows) and `code` (not in windows).

| Section | Why it's interesting for NLI |
|---|---|
| `retrying-requests` | defaults ("3 times", "up to 3 redirects"); most info is in code, so the prose windows are thin lead-in sentences |
| `configuring-exponential-backoff` | numbers, units, negation ("does not sleep"); the formula is a literal block, so it's **not** in any window and the next paragraph starts with a dangling "seconds, …" |
| `using-timeouts` | units, an example value only in code (3.0), override rule; same topic as the httpx section |
| `changelog-2-8-0-security` | changelog (SPEC §6.4 covers it): severities, a `caution` admonition, "no longer" |
| `changelog-2-8-0-bugfixes` | long (928 tokens, 3 windows @ 400): versions, "instead of", swapped names; overlaps the Security fix |
| `httpx-timeouts-fine-tuning` | second library, Markdown; parallel definitions (connect/read/write/pool) that are easy to swap |

## Layout

```
nli_mock.py   build chunks/prompts/windows, pair claims       prompt.md   extractor prompt template
                                                              prompt-outside.md  prompt for realistic unsupported claims
nli_run.py    run NLI models as a tracked run                 labels.csv  expected verdicts
FINDINGS.md   what we learned, per run                        runs/       one folder per run + INDEX.md
sections/<slug>/
  section.json                 simulated Sphinx parse (input, hand-written)
  prompt.md                    ← paste into a model           (generated by build)
  prompt-outside.md            ← paste into a model           (generated by build)
  chunk.md  chunk.json         the chunk as the extractor sees it (generated)
  windows-400.json  windows-128.json   NLI windows             (generated)
  claims/<model>.json          ← paste the model's JSON answer to prompt.md here
  claims/<model>-outside.json  ← paste the answer to prompt-outside.md here
  claims/negatives-handmade.json       hand-written wrong claims
  pairs/<model>.windows-<N>.jsonl      NLI pairs              (generated by pair)
  pairs/x-<other>~<model>.windows-<N>.jsonl  cross-section pairs (generated by cross)
```

## Steps

```sh
# 1. chunks, prompts, NLI windows (real DeBERTa-v3 tokenizer, no torch needed)
uv run experiments/nli/nli_mock.py build                    # 400-token windows (SPEC candidate)
uv run experiments/nli/nli_mock.py build --max-tokens 128   # small windows, exercises boundaries

# 2. paste sections/<slug>/prompt.md into a model, paste its answer into
#    sections/<slug>/claims/<model>.json  (any file name = extractor label)

# 3. citation check + premise selection for every non-empty claims file and window size
uv run experiments/nli/nli_mock.py pair                     # or: pair <slug> ...

# 4. cross-section pairs: each real claim vs the most word-similar sentence of a related
#    section (CROSS_GROUPS in nli_mock.py). Gold = must not be kept. Re-run after pair.
uv run experiments/nli/nli_mock.py cross
```

Where should-drop claims come from (reported separately per source in each summary): `negative` (hand-made twists: numbers, negations, swaps), `outside` / `beyond` (from `prompt-outside.md`: true-but-not-stated, and overreaching claims written by a model), `cross` (a claim checked against the wrong section), and `real` extractor claims labelled neutral.

Each line in `pairs/*.jsonl` has `premise` (NLI window, or two joined windows when the citation crosses a boundary) and `hypothesis` (the claim), ready for `CrossEncoder.predict([(premise, hypothesis)])`. Claims whose citation is not verbatim in the chunk, or is only in code, are kept with a `dropped:*` status, so you can count them. Empty claims files are skipped.

## Run the NLI models (tracked runs)

```sh
uv run experiments/nli/nli_run.py --name baseline --note "why this run"     # SPEC candidate model, window only
uv run experiments/nli/nli_run.py --model cross-encoder/nli-deberta-v3-xsmall \
    --model MoritzLaurer/DeBERTa-v3-large-mnli-fever-anli-ling-wanli \
    --context none breadcrumb sentence --name compare                        # several models x premise contexts
```

`--context` puts something in front of the premise: `none`, `breadcrumb` (`urllib3 > User Guide > …:`) or `sentence` (`This text is from the urllib3 documentation, section "…".`).

`--premise window local`: `window` = the NLI window, `local` = only the cited sentence(s) ± `--radius` (default 1). Giving both also reports `both` = keep only if both say entailment. Every summary has a threshold sweep (keep if p_entailment ≥ 0.3 / 0.5 / 0.7 / 0.9 vs argmax).

Speed (CPU):
- **Score cache** `.cache/scores.jsonl` (gitignored): keyed by model + HF revision + variant + premise + hypothesis, so a run only scores pairs it hasn't seen. `--no-cache` ignores it; `--import-cache runs/001-… runs/002-…` seeds it from older runs' CSVs.
- Models are always loaded in **fp32**. transformers 5 otherwise keeps the checkpoint dtype, and the large model's checkpoint is fp16, which is ~9× slower on CPU (runs 001/002 hit this).
- `--threads N` sets torch CPU threads (default = torch's, which was fastest in run 003); `--batch` defaults to 8 (less padding).
- Model families: 3-label NLI cross-encoders, and two binary fact-checkers built for grounding claims in a document: **MiniCheck** (`lytang/MiniCheck-DeBERTa-v3-Large`, `lytang/MiniCheck-RoBERTa-Large`; input `doc + eos + claim`) and **HHEM-2.1-open** (`vectara/hallucination_evaluation_model`, needs `trust_remote_code`, so its code revision is pinned in `PINNED`). Binary scores map to entailment = p_supported, neutral = 1 − p, contradiction = 0 (contra recall is `n/a`).
- `--model <id>@int8` = dynamic int8 quantization of the Linear layers. ~1.6× faster but **broken for the large DeBERTa** (0/16 labels agree with fp32, run 003); kept only for benchmarking.
- `--bench N --threads 2 4 6 0` times N long sample pairs per model × thread count (no cache, no scoring run) and writes `runs/NNN-<name>/bench.md`.

Nothing is installed into the repo or the workspace `.venv`: dependencies (CPU `torch`, `transformers`) are declared inline in the script, so `uv` builds a cached environment for it (`%LOCALAPPDATA%\uv\cache` / `~/.cache/uv`). Model weights go to the Hugging Face cache (`~/.cache/huggingface/hub`, move it with `HF_HOME`). Delete them with `uv cache clean` and by removing that folder.

Every invocation is a **run** in `runs/NNN-<name>/` (`config.json` with git commit, models, versions, input hashes and timing; `results/*.csv`; `summary.md` with metrics and every wrong decision) plus a line in [`runs/INDEX.md`](runs/INDEX.md). Analyses computed afterwards from a run's CSVs (no model calls) go in that run's `posthoc/` folder with the script that produced them. Never edit or delete old runs; what we learned goes to [`FINDINGS.md`](FINDINGS.md).

**Picking this up:** read the last section of [`FINDINGS.md`](FINDINGS.md) ("Status after run 006") for the current recommendation and the open items. The score cache is not committed, so your first run scores everything again (run 006 took ~1 h on a 10-thread laptop CPU; the first run also downloads ~6 GB of model weights for the run 006 models, 3.3 GB of it MiniCheck).

## Labels and negatives

- [`labels.csv`](labels.csv): expected verdict per claim = *should grounding keep this claim?*, judged against the whole section's prose read as part of the urllib3 docs (so "urllib3's Retry" is supported; a fact only in code is not). Uncertain ones are `borderline=yes`. **Drafted by Claude (`annotator=claude-draft`); review them and put your name in `annotator`.**
- `claims/negatives-handmade.json` in each section: hand-written wrong claims (changed numbers, negations, outside knowledge). Without them every real claim is "entailment" and a model that always says yes would look perfect.

Citation matching ignores backticks and whitespace differences (the windows are plain text, the chunk shown to the extractor is Markdown). Answers wrapped in a ```json fence or with typographic quotes are accepted.
